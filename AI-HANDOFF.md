## 1. What this project is

A **private, single-user trading desk** that runs entirely in the browser. No sign-up, no subscription,
no server, no telemetry, no pricing tiers of any kind. Everything is unlocked because there is exactly
one user: the owner.

It was built after the owner reviewed https://pipflow.org and asked for something similar in function
but **original in design** and **~10× deeper in features**. The visual language is deliberately
different from the reference: graphite surfaces (`#0a0b0d`), amber accent (`#f5a524`), monospace
numerics, a persistent left rail. The reference's violet/emerald marketing aesthetic, hero sections,
bento grids, and pricing tables were explicitly rejected and must not be reintroduced.

**Brand:** "PipSage Desk". Renameable in one place (`BRAND` in `build.js`).

---

## 2. Hard constraints — do not violate these

These came directly from the owner and are non-negotiable:

1. **No pricing, plans, tiers, paywalls, upgrade prompts, or "free vs pro" anything.** Every feature
   is available. Never add a subscription surface.
2. **Do not copy the reference site's interface.** Functional equivalents are fine (assistant, charts,
   backtesting, risk controls, journal). Its colours, fonts, layout patterns, copy, and component
   shapes are not.
3. **Single user, local-first.** No accounts, no login servers, no analytics. Data lives in the
   browser's `localStorage`.
4. **Self-contained static site.** No build dependencies, no npm install, no framework, no bundler.
   Pure HTML/CSS/JS generated by a plain Node script.
5. **Honesty over polish.** Where the app cannot do something (live prices, broker execution, AI
   reasoning), it says so in the UI. Never fake a capability. The "sample feed" label on prices
   exists for this reason — do not remove it.

## 3. Architecture

```
pipsage/
├── build.js                 # builder: BRAND, PAGES, inlines css+js into each shell
├── render.yaml              # public Render Static Site Blueprint
├── README.md                # user-facing docs
├── AI-HANDOFF.md            # this file
├── index.html               # meta-refresh → dashboard.html
├── *.html                   # 14 generated pages (~296 KB each, fully inlined)
└── src/
    ├── desk.css             # design system: tokens, shell, panels, tables, charts, responsive
    ├── desk-core.js         # store, utils, indicators, seed, shell, palette, gate, PS.mount()
    ├── desk-charts.js       # canvas chart engine + SVG equity/spark/donut helpers
    ├── desk-ui.js           # PS.ui: panels, KPI tiles, tables, forms, money/risk helpers
    ├── desk-page-dashboard.js
    ├── desk-page-charts.js
    ├── desk-page-positions.js   # also contains PS.pages.journal
    ├── desk-page-build.js       # strategies + backtest lab + PS.backtest() engine
    ├── desk-page-risk.js        # risk console + analytics
    └── desk-page-rest.js        # assistant, calendar, notes, tasks, playbook, settings
```

**Build:** `cd pipsage && node build.js` → writes 15 files. No dependencies. Runs in ~200 ms.

**Why generated pages:** each HTML file is a self-contained shell with CSS and all nine JS files
inlined. This means (a) you can open any `.html` by double-click with no server, and (b) there are no
relative-path or CORS problems. The cost is duplication — never edit the `.html` files by hand, they
are overwritten. **Always edit `src/` and rebuild.**

## 4. The money maths — the part that must stay correct

This was the single biggest source of bugs. Every P&L figure in the app flows through these helpers
in `desk-core.js`. **Never compute P&L ad hoc in a page.**

```js
PS.contractOf(symbol)                       // contract size, e.g. 100000 for FX, 100 for XAUUSD
PS.quoteCcy(symbol)                         // 'USD' | 'JPY' | ...
PS.pnlFor(symbol, side, lots, entry, exit)  // realised P&L in USD
PS.rFor(symbol, side, lots, entry, exit, stop)  // R multiple
PS.riskCashFor(symbol, lots, entry, stop)   // cash at risk to the stop
```

Core formula:

```
contract size × lots × price move ÷ quote-currency rate to USD
```

**Contract sizes** (stored on each `SYMBOLS` entry):
FX **100,000** · XAUUSD **100** · XAGUSD **5,000** · BTC/ETH **1** ·
NAS100/US30/SPX500/GER40 **1** · USOIL **1,000**

USDJPY converts through its **exit** rate. An earlier version used a naive `unit` multiplier
(Forex 100000 / Metals 100 / Crypto 1 / others 10) which produced absurd results (+$43,200 on a
USDJPY trade, +$6,200 on silver). That approach is dead — do not revive it.

**Seed account** (must stay believable, not flattering): $25,000 opening balance, **+$4,734.82**
realised over 15 closed trades, 73.3% win rate (11W/4L), profit factor 5.27, expectancy $315.65,
avg win $531.26, avg loss $277.25, max drawdown −$356. Open positions are sized *within* the 1.25%
per-trade limit so the risk console's audit reads "all positions within limits" on first open.

## 5. Design system

Tokens live at the top of `src/desk.css`.

- **Surfaces:** `--bg` `#0a0b0d`, panels `#101216`-ish, borders `#ffffff12`
- **Accent:** amber `#f5a524` (price/action), teal `#2dd4bf` (support), green `#3fd68b` (up),
  red `#f2555a` (down)
- **Type:** system sans for prose, `ui-monospace` for every number (`font-variant-numeric: tabular-nums`)
- **Light theme:** `[data-theme="light"]` on `<html>`, toggled in the topbar, persisted
- **Radii:** sm 8 / md 12 / lg 18
- **Numerics are always monospace and tabular** — columns must align

Responsive breakpoints: 1240 / 1080 (rail collapses to icons) / 860 / 620 (rail becomes a bottom bar)
/ 420. On phones, KPI tiles go 2-up and the charts page lifts the chart above the symbol list.

## 6. State and data

- Everything under `pipsage.*` keys in `localStorage`. See the `KEYS` map in `desk-core.js`.
  **Both `journalEntries` and `reflections` point at the same key** — this was a real bug (seeded
  reflections were written but never read) so keep them in sync if you refactor.
- `PS.Store.get(key, fallback)` / `.set(key, value)`. Settings live in `pipsage.settings`.
- **Access lock** (`pipsage.lock`) is a local convenience gate, *not* encryption. The UI says so.
  If a user forgets a passphrase, Settings offers a lock-screen **reset** that clears only the lock.
- **Export** = one JSON file of every key. **Import** restores it. **Load demo** explicitly reseeds.
- **Delete everything** clears user records/settings and persists `pipsage.seed-disabled`, so the next
  visit stays empty instead of silently restoring sample trades. The seed-disabled marker is
  included in export/wipe bookkeeping; Load demo data removes it and reseeds.
- `PS.seed()` writes demo data on first visit unless `pipsage.seed-disabled` is true.

## 7. Known-good verification procedure

Playwright is available in this environment but needs a library path:

```bash
export LD_LIBRARY_PATH=/tmp/libs/root/usr/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH
```

Standard sweep — run this after any change:

1. Build: `node build.js`
2. Load all 14 pages at **1440×1000, 1024×900, 390×844**
3. Assert on every page: **zero `pageerror`, zero console errors, `#app > *` count ≥ 2**,
   and `document.documentElement.scrollWidth <= window.innerWidth + 2` (no horizontal overflow)
4. Exercise interactions: Ctrl+K palette, theme toggle + persistence across reload, alerts drawer,
   log-trade modal (check the live P&L/R preview), filters, CSV export, note create, risk-limit save,
   backtest re-run
5. Reload and confirm writes persisted

Last full run: **42 combinations (14 pages × 3 viewports) → 0 errors, 0 overflow, 0 blank pages.**

### Gotchas that already cost time — do not relearn them

- **`type="number"` inputs reject thousands separators.** `value="25,000"` renders empty and silently
  breaks the sizer. `PS.ui.field` strips commas for numeric inputs — keep that.
- **Canvas elements need an explicit `width: 100%`** in CSS or they sit at the default 300 px.
- **Full-page screenshots hide layout bugs.** Use viewport screenshots + DOM probes
  (`getBoundingClientRect`, `getComputedStyle`).
- **`PS.ui.table` must tolerate columns with no label** (sparkline columns) — blank `<th>`, never
  `esc(object)`.
- **A separate `PS.boot` must not come back.** All entry points route through `PS.mount()`, which adds
  the `.main` class to `#app` (without it, content slides under the rail).
- Canvas label collision: the live price tag owns ~19 px of the right axis. Axis ticks and level
  labels must skip that band.

## 8. What is honestly missing (and why)

These are real limitations, stated in the UI, and are the natural next steps:

| Gap | Current state | What it needs |
| --- | --- | --- |
| **Live prices** | Seeded sample feed, labelled "sample feed" | A price source; `PS.price()` and the candle generator are the swap points |
| **Broker execution** | None. Accounts are labels only | Broker API (MT5 via MetaApi, or OANDA/IBKR REST) |
| **Broker import** | Manual entry + CSV paste | Statement parser (MT5 HTML/CSV, cTrader, broker-specific) |
| **Assistant** | Rule-based over local data, honest about unknowns | Optional LLM call; the data-shaping layer already exists |
| **News/calendar** | Seeded static events | Economic calendar API |
| **Multi-device sync** | localStorage only | Export/import is the current answer; would need a backend |
| **Tests** | None committed | Playwright suite using §7 as the spec |

## 10. Repository and deployment

`render.yaml` defines a public Render Static Site. It runs `node build.js` and publishes the
repository root. Connect this repository in the Render dashboard as a Blueprint to create the site.
The Render connector is not available in this Arena session, so the service has not been created or
deployed from here.

This checkout does not include `.gitignore`, `LICENSE`, or the GitHub Pages workflow mentioned by
an earlier brief; those are separate repository setup items and are not required by the Render
Blueprint.

The current deployment is static and sample-only: market data is not live and no broker is connected.
Trade/journal data remains in each visitor's browser `localStorage`; a public URL does not share
that data between browsers.
